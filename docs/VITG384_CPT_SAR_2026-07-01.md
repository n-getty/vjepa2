# ViT-g @ 384 surgical CPT — training + SAR downstream (through 2026-07-01)

Companion to `docs/fs10_probe_findings.md` (which covers the earlier **ViT-L** v1/v2/v3
lineage). This doc covers the **pivot to undistilled ViT-g @ native 384** and its
SAR-RARP50 asformer results across the base run, constant-LR resumes, and 64f cooldown.
The triplet tool-recognition results for the same e19 checkpoint are in
`docs/TRIPLET_RESULTS_2026-07-01.md`.

## ★ SUMMARY ★

The ViT-g @ 384 CPT worked and **resolved the v3 regression by construction.** SAR
asformer macro-F1 rose **monotonically** across the whole 20-epoch run, peaking at
**e19 = 75.56** (+3.23 over the Meta-g@384 anchor 72.33). On the metric that compares
to published work, **e19 is SOTA on SAR-RARP50 action segmentation: F1@10 = 85.41 on
the official test set vs the 84.10 SOTA (+1.31).**

After e19 it **plateaued**: neither constant-LR resume (e24–e34) nor a 64-frame
cooldown (e5–e10) beat e19.

**e19 is the checkpoint to ship.** No further-pretraining lever improved SAR;
downstream gains now come from probe/readout choices (see the triplet doc's
topk_mean result), not more CPT.

## Why ViT-g @ 384 (the pivot, 2026-06-26)

The ViT-L v3 investigation found the "surgical CPT regresses downstream" effect had
two real drivers, **both dissolved by one backbone swap**:

1. **Un-distillation drift.** ViT-L Meta init was *distilled from ViT-G*; CPT relaxed
   it out of the ViT-G basin (drift was global — kinetics cos-to-Meta fell as much as
   surgical). Starting *from* undistilled ViT-g removes the basin to fall out of — no
   distillation-anchoring hack needed.
2. **Resolution mismatch (dominant artifact).** v3 trained at 256 but init and probe
   were 384; the train256/probe384 penalty grew each epoch. Training at native 384
   removes it end-to-end.

Rejected: ViT-L + frozen-Meta distill anchor (patches only #1), ViT-B (distilled,
weaker), from-scratch (corpus too small). See the `optimal-cpt-vitg384` /
`v3-regression-rootcause` history.

## Config

`configs/vitg16_surg_vid_webdataset_single4/vitg384_cleandata.yaml`. Clean diff from
the v3 ViT-L config: `model_name: vit_giant_xformers`, `crop_size: 384`, the ViT-g
checkpoint + keys. Key points, all verified:

- **Checkpoint** `vjepa2_1_vitg_384.pt` (16.9GB, official). Keys are
  `encoder`/`target_encoder` (NOT `ema_encoder` like the ViT-L file) → config sets
  `context_encoder_key: encoder`, `target_encoder_key: target_encoder`,
  `checkpoint_key: target_encoder` for probes (target = published EMA extractor).
- **Two v3-isolation inheritances fixed for an "optimal" run:**
  - Context loss `lambda_value_vid: 0.0` (v3 ablation) → **0.5** (the defining 2.1
    feature). The Lambda warmup ramp was hardcoded for Meta's ~300k-iter run so it
    never fired on our 10k-iter run; made it config-driven
    (`model.lambda_start_iter/lambda_end_iter`, set 500→1500).
  - `load_predictor: false` → **true** (warm-starts Meta's predictor; needed for the
    context head).
- Load verified on-device: encoder 494/494, target 494/494 (100%); predictor
  308/322 (95.7%, the 14 "missing" are extra mask_tokens, zero-init + modulo-indexed,
  harmless).
- Topology: Aurora 16 nodes × 12 tiles × bs2, weak scaling. `torch.compile` off (XPU).
- Launch knobs: `VJEPA_BF16_COMM=1`, `VJEPA_DDP_BUCKET_MB=50`. LR 7.5e-5 / warmup 2 /
  20 epochs (CPT-tuned on ViT-L — carried over; loss stayed healthy on ViT-g).

## Training run

- **Complete 2026-06-28:** all 20 epochs, `latest.pth.tar` epoch=20, milestones
  e4/e9/e14/e19 (every-5). ~21h wall on the debug-scaling self-resubmitting 1h chain
  (~50min/epoch compute + ~10min staging/slice). Lost ~1h to one slice that hung at
  iter ~4 (isolated dataloader/collective stall; successor resumed clean).
- Pretrain pred-loss FLAT ~0.30 across all epochs (expected for CPT from a converged
  init; pretrain loss is a poor downstream proxy — only probing tells us).
- Checkpoints on Flare:
  `/flare/ModCon/ngetty/checkpoints/surg_2_1_vitg384_cleandata/vitg384_n16g12_weak/`.

**Scaling note (measured):** ViT-L 256px bs2/rank 1n→16n = ~78% per-GPU efficiency.
Key reframe: backward is 3.3× forward *at 1 node* (mostly intra-node sync across the
12 tiles), so 1n→16n adds only ~+713ms inter-node allreduce, not an exploding penalty.
fwd-context is identical (585ms) at 1n and 16n = clean weak-scaling.

**Chain gotcha (learned):** the `ngetty` account is **shared across independent
agents**; debug-scaling has max_run=1 + Q-threshold=1 per user. A co-tenant's job can
hold the single Q-slot exactly when a chain slice tries to qsub its successor →
`qsub` fails, error swallowed, chain dies silently. Robust fix = external watchdog
cron that re-qsubs if no `vitg_chain` is R or Q, fully decoupled from any slice.

## SAR-RARP50 asformer downstream (the arbiter)

Cached asformer probe @ 384 (export features once → train head on cache). Metric =
`val_macro_f1` at peak (early-stopped). Anchor = **Meta ViT-g @384 = 72.33**
(itself ~1.1 *below* raw ViT-L@256 73.44 — bigger undistilled backbone ≠ higher probe
F1 by default; the CPT run's job was to lift ViT-g above *its own* 72.33).

Probe recipe/scripts: `configs/heads/sarrarp50/full_cached_384/`,
`scripts/vitg_probeonly_capacity.sh` (4h capacity, skips export; use this, NOT the 2h
export+probe combo which walltime-killed mid-probe). Cache ~490G/ckpt (3.2× the 256
cache) — delete-after-probe.

### Base run — MONOTONIC RISE (thesis confirmed)

| ckpt | macro-F1 @384 | vs Meta-g (72.33) | Δ from prev |
|------|---------------|-------------------|-------------|
| Meta-g (e0) | 72.33 | anchor | — |
| e4  | 73.41 | +1.08 | — |
| e9  | 73.66 | +1.33 | +0.25 |
| e14 | 74.23 | +1.90 | +0.57 |
| **e19** | **75.56** | **+3.23** | **+1.33** |

Monotonic and *accelerating* — the **opposite** of the v3 ViT-L curve (peaked e9 then
declined by e14 = the un-distillation signature). Starting from undistilled ViT-g
eliminated the drift, exactly as the pivot predicted. e19 is the peak.

### Segmental F1@k — e19 is SOTA on SAR-RARP50 (official test set)

Macro-F1 (frame-level) can't be compared to the published SAR-RARP50 SOTA (F1@10 =
84.10); segmental F1@k can. Ported Leonardo's `eval_segmental_f1.py` to Aurora
(`scripts/eval_segmental_f1.py` + `run_segmental_f1_aurora.sh`, capacity queue, single
XPU tile, inference-only from a probe's `best.pt`; live encoder + 3-head softmax
ensemble + stitched per-video timelines = the challenge protocol).

**e19 official held-out TEST set (videos 41–50, disjoint from train+val):**

| metric | e19 | SOTA |
|--------|-----|------|
| **F1@10** | **85.41** | 84.10 (**+1.31**) |
| F1@25 | 83.74 | — |
| F1@50 | 78.27 | — |
| edit  | 81.20 | — |
| per-frame macro | 69.19 | — |

**Our ViT-g surgical CPT is SOTA on SAR-RARP50 action segmentation by F1@10.**
For reference e14 was F1@10 = 81.22 (val), so e14→e19 jumped +4.19 — consistent with
the macro-F1 climb. Val F1@10 (85.41, 6 videos) and test F1@10 (85.41, 10 videos)
came out coincidentally identical → val and test agree, validating that val-based
decisions transfer to test.

Notes:
- **Val/test policy:** val set for ALL design/checkpoint decisions (no test leakage);
  test set ONLY for final SOTA numbers on the best checkpoint. Test CSV:
  `/flare/ModCon/ngetty/surg_2_1_v1_probes_aurora/csv/sarrarp50_actions_4fps_asformer_ctx3_seq_test.csv`.
- segf1 per-frame macro (69–71) ≠ cached-probe macro-F1 (75.56) for the same e19 — not
  a bug, different protocols (live 3-head ensemble + stitched timelines vs single-head
  per-clip cached features). Both say e19 is excellent.
- **Horizontal-flip TTA = dead end** (85.41 → 85.33, noise): surgical video has strong
  L/R structure (instruments enter a consistent side), so a flipped view is OOD.
- Device gotcha: `ZE_AFFINITY_MASK=0.0` makes Level-Zero report 0 devices → silent CPU
  fallback; use `ZE_FLAT_DEVICE_HIERARCHY=FLAT` for single-process XPU jobs.

### Constant-LR resume (cresume) — FLAT, slightly eroding

Continued the run past e19 at constant LR to test whether more steps help:

| ckpt | macro-F1 @384 |
|------|---------------|
| e19 (peak) | 75.56 |
| cr24 | 75.47 |
| cr29 | 75.36 |
| cr34 | 74.36 |

Drifts slightly **down** e19→e34 (−1.2), never up. Constant-LR resume does not
improve SAR. **Discontinued.**

### 64-frame cooldown — mild climb, still below e19

Cosine cooldown to ~1e-6 at 64 frames/clip (temporal lever), 20 epochs, init from e19:

| ckpt | macro-F1 @384 |
|------|---------------|
| cd64f e5  | 73.83 |
| cd64f e10 | 74.54 |

Inches up (e5→e10 +0.7) but stays ~1pt below the e19 plateau. Cooldown ran to
completion (20/20); orchestrator set to STOP. **Did not beat e19.**

Walltime lesson: 64f is ~14.3 s/iter (16.9 p90) + ~5min staging/slice → does NOT fit
a 1h debug-scaling slice at ipe=500/200. Use **ipe=150 + capacity queue** for 64f;
match queue walltime to per-epoch cost (do the p90 arithmetic before claiming "fits").

## Bottom line

- **Ship e19.** It is the SAR peak (75.56, +3.23 over Meta-g), reached by a clean
  monotonic CPT rise.
- **SAR is saturated for this recipe+data.** No pretraining lever (cresume, 64f
  cooldown) beats e19. Consistent with the triplet finding: the remaining downstream
  gains are a **readout/probe** problem (topk_mean pooling), not more CPT steps.
- Open lever not yet run: **surgical-heavy data reweight** (82% surgical) as a fresh
  full-LR arc — staged config `vitg384_surgheavy.yaml`, deliberately NOT combined with
  cooldown (for attribution + plasticity). This is the next thing to try if we want to
  move SAR/triplet further at the encoder level rather than the readout.
